# 音效提案 — TKU BridgeTable · 淡江牌桌

> **狀態：已確認（社長 2026-10-25）。** 照 §9 的建議（★）全部採用，並讓每位社員在「我的帳號 → 音效」自己選：風格 A「實體牌桌」預設、B「簡潔電子」可選、另有「關閉」（C 不當風格，改成「震動提醒」選項）；音量輕／中／大（預設中）；叫品聲預設關；新社員預設開。定案的內容在 `DESIGN.md` §4.1，程式在 `src/lib/sound/`。以下保留提案原文作為紀錄；§1「現況」描述的是定案前的狀態。
>
> **試聽：** 用 Chrome、Edge、Firefox 或 Safari 直接打開同一個資料夾的 [`demo.html`](demo.html)（在檔案總管雙擊即可，不需要網路、不需要伺服器）。先點一下頁面任何地方，瀏覽器才允許出聲。

## 1. 現況

目前的音效在 `src/lib/sound.ts`，全部用 Web Audio API 即時合成，沒有任何音檔（`DESIGN.md` §4「音效」）：

| 事件 | 現在的聲音 | 觸發處 |
| --- | --- | --- |
| 發牌（新的一副） | 洗牌的「嘩啦」：0.6 秒內 48 下紙聲，最後兩下整牌 | `TablePage` 的 `useTableSounds` |
| 出牌（任何人） | 牌落桌的「咻—啪」，在出牌後 0.95 秒、跟 1.3 秒的滑動同時落定 | 同上 |
| 輪到你叫牌 | BBO 式的木質「咚」（247 Hz） | `useTurnAlert` |
| 輪到你出牌 | 只有分頁在背景時才「咚」，分頁標題加「🔔」 | 同上 |
| 你拖太久（慢出提醒） | 同一聲「咚」 | `TablePage` 的 `slowSeat` |

開關只有一個：頁首的喇叭按鈕（手機在「我的帳號 → 音效」），存在瀏覽器的偏好設定 `sound`，預設**開**。沒有音量設定；一墩結束、叫品、攤牌、合約結果、聊天、通知、挑戰、隊制賽都沒有聲音。

## 2. 原則

1. **細、短、像真的牌桌。** 參照 BBO：社員打 BBO 習慣了「啪」的出牌聲與「咚」的輪到你，牌桌上的聲音延續這個手感，不加音樂、不加語音、不加「叮叮噹噹」的遊戲效果。
2. **打兩個小時也不煩。** 一副牌最多 52 張出牌聲加十幾個叫品，聲音必須短（出牌 < 0.1 秒）、輕（比「輪到你」小 6–12 dB）、每次略有不同（音量音高 ±10%），避免機械感。會重複上百次的聲音一律不帶旋律。
3. **聲音只是提醒，不是資訊。**（無障礙）任何聲音傳達的事，畫面上一定也有：輪到你有黃框閃動與分頁標題，攤牌有對話框，合約結果有結果面板，聊天有未讀數。關掉聲音、聽不見的社員不會漏掉任何事。反過來，**不靠聲音區分好壞**：做成與倒約、贏墩與輸墩若要不同聲音，差別只在音色，不能讓人只聽聲音就以為自己知道結果而不看畫面。
4. **尊重靜音與音量。** 喇叭按鈕關掉時完全不出聲（包括通知）。新增一個音量設定（§6），所有聲音都過同一個總音量與壓縮器，不會爆音。分頁在背景時只播「需要你」的聲音。
5. **需要你做事的聲音最清楚，其他的退到後面。** 分三級：
   - **呼叫**（要你動作）：輪到你、有人攤牌或要求撤回等你回應、慢出提醒。最大聲（基準 0 dB）。
   - **事件**（重要但不必立刻動作）：發牌、合約結果、隊制賽開始／結束、挑戰結果出爐、私訊。−6 dB。
   - **環境**（桌上正在發生的事）：出牌、一墩收走、叫品、聊天。−10 到 −20 dB。
6. **不在不該響的時候響。** 重播、觀看別人的牌局、斷線重連補資料、一次進來好幾個動作時都不該一連串地響（§4 的「不播放」欄）。
7. **沒有授權問題。** 全部用 Web Audio 合成（§7），不用別人的音檔。

## 3. 三種風格

`demo.html` 每個事件三種風格各一個按鈕，可以並排比較。

| | A 「實體牌桌」（建議） | B 「簡潔電子」 | C 「無聲＋震動」 |
| --- | --- | --- | --- |
| 感覺 | 紙牌落在絨布上、木頭叫牌盒、木琴 | 柔和的電子點擊與鈴聲，像手機 App | 不出聲；手機震一下，電腦只有畫面提示 |
| 出牌 | 「咻—啪」（現在的聲音） | 很短的「嗒」 | 不震（太頻繁） |
| 輪到你 | 木質「咚」（現在的聲音） | 一聲「叮」 | 震 40 ms |
| 結果、通知 | 木琴 1–3 個音 | 電子鈴 1–3 個音 | 短震的節奏 |
| 適合 | 桌機、筆電；跟 BBO 最像 | 喜歡乾淨聲音、在吵雜環境的人 | 上課、圖書館、宿舍，或手機開靜音的人 |
| 缺點 | 合成的紙聲在很小的手機喇叭上比較薄 | 跟 BBO 的手感差最多，久了比較「電子」 | iPhone 的 Safari **不支援網頁震動**，只剩畫面；Android Chrome 才會震 |

**建議：A「實體牌桌」為預設**，理由是它就是現在的聲音延伸出來的（出牌、發牌、輪到你不變），社員不用重新習慣，也最接近 BBO。B 可以做成設定裡的選項（成本很低，同一套合成程式換參數）。C 不建議當成獨立風格，而是當成**手機上的附加選項**「震動提醒」：只在「呼叫」級的事件震動，聲音照常依開關。

| 12 | **私訊、通知鈴** | 木琴兩個音（同音高、輕） | 0.35 s | −8 dB | 自己送出的；那個對話框正開著；免打擾時段（若之後加）；在牌桌上正在出牌的那一刻延後到這一墩收走 |

| 15 | **隊制賽：比賽開始**（兩室同時發第 1 副） | 木琴三個音上行（琶音），接著 #1 發牌 | 1.0 s | −6 dB | 觀看者；重新整理頁面時 |
| 16 | **隊制賽：另一室的成績進來／比分更新** | 一下最輕的木琴高音 | 0.25 s | −16 dB | 參賽者正在出牌時延後到這一墩收走；預設只有觀看者聽得到（§9 Q8） |
| 17 | **隊制賽：比賽結束** | 木琴四個音的短句，**勝負同一聲** | 1.2 s | −6 dB | 重播；之後再打開歷史紀錄 |

**全域的「不播放」規則**（每個事件都適用）：

- 喇叭按鈕關掉、音量 0：什麼都不播。
- **重播**：牌局紀錄（`BoardPage`、`HistoryPage` 的 Handviewer）、`ReplayControls` 一律不出聲。
- **斷線重連、重新整理、剛進牌桌**：伺服器一次補上的狀態不當成新事件。只有在畫面已經穩定之後才發生的變化才播。
- **節流**：同一種聲音 120 ms 內只播一次；一次進來的多個動作（例如機器人連出兩張被一起送到）只播最後一個。機器人的出牌間隔是 1.4 秒，不會擠在一起，所以平常一張一聲。
- **觀看（kibitz）**：只播 #1–#4（桌上的聲音，可在設定關掉），不播任何「呼叫」級的聲音。隊制賽的觀看者同時看兩室時，只播目前畫面上那一室。
- **分頁在背景**：只播「呼叫」級（#5、#6、#8、#10）與 #12 私訊；出牌、叫品、聊天不播。
- **系統設定「減少動態效果」**不影響聲音（那是畫面的設定）；聲音只看喇叭按鈕與音量。

## 5. 出牌的時間點（「示範一墩」）

聲音跟著畫面，不跟著伺服器：

```
0.00 s  西家（機器人）出牌，牌開始滑動 1.3 秒
0.95 s  ……「啪」（別人出牌，−12 dB）
1.40 s  北家出牌
2.35 s  ……「啪」
2.80 s  東家出牌
3.75 s  ……「啪」
        輪到你：分頁在前景時只有黃框，不出聲（背景時「咚」）
4.60 s  你出牌（約 0.8 秒的思考）
5.55 s  ……「啪」（自己出牌，−8 dB）
6.60 s  贏的牌亮框；四張牌被掃走「唰」（−16 dB），1.3 秒
```

`demo.html` 的「示範一墩」照這個時間表播放，並在畫面上同步標出現在是哪一家，三種風格各一個。另有「示範一副的結尾」：最後一墩 → 合約做成。

## 6. 音量

- 頁首的喇叭按鈕維持「開／關」（點一下就靜音，最常用）。
- 「我的帳號 → 音效」加一個**音量**：建議三段「輕／中／大」（−12／−6／0 dB，預設「中」），比滑桿好懂、手機好按。另一個選項是 0–100 的滑桿（§9 Q2）。
- 所有聲音過同一個 `GainNode`（音量）→ 壓縮器 → 喇叭，相對響度（§4）固定，社員只調總音量。
- 新增的聲音類別各自可以關（設定裡一排勾選）：「叫品聲」、「聊天聲」、「觀看時的聲音」。其他跟著總開關。

## 7. 檔案格式與大小

- **建議：不用音檔，全部用 Web Audio 合成**（跟現在一樣）。好處：沒有下載（0 KB 音檔），第一次播放沒有延遲，每次可以隨機微調避免機械感，音色與音量可以用程式調，沒有任何授權問題。
- 程式的預算：合成程式（三種風格的參數表）壓縮後 **≤ 6 KB**，只在進入牌桌、隊制賽、挑戰頁面時載入（動態 import），不影響大廳的首次載入。
- 如果將來改用錄音的音檔：一律 **單聲道 Opus（`.ogg`／`.webm`）48 kbps**，Safari 舊版另備 AAC（`.m4a`）；每個檔 **≤ 15 KB**、全部 **≤ 120 KB**；第一次進牌桌時預載。音檔放 `public/sounds/`，用 Web Audio 解碼一次後重複播放（不用 `<audio>` 元素，iPhone 上延遲太大）。
- 執行時的成本：每個聲音是幾個振盪器或一段雜訊，播完自動釋放；一秒的白雜訊緩衝只產生一次（約 190 KB 記憶體）。

## 8. 授權

- **自己合成的聲音沒有授權問題**：只有程式碼，跟專案的其他程式一樣。
- 現在的出牌與「咚」是**參照 BBO 量過頻譜與音量包絡後重新合成**的仿製，沒有複製 BBO 的音檔（`cardplay.mp3`、`myturn.mp3`）；之後也不把 BBO 或其他網站的音檔放進專案。
- 如果真的需要錄音：只能用**社員自己錄的**（寫明錄音者同意以專案授權釋出）或 **CC0**（公眾領域，例如 Freesound 上篩選 CC0 的檔案）。每個檔在 `public/sounds/LICENSES.md` 記下來源網址、作者、授權。不用 CC-BY（要在介面上標示作者，麻煩）、不用 CC-BY-NC 或「免費下載」但授權不明的音效包。

## 9. 請社長決定

勾選或寫下意見即可；★ 是建議。

1. **風格**：☐ ★ A「實體牌桌」為預設　☐ B「簡潔電子」為預設　☐ A 預設、B 當設定裡的選項（★ 一起做）
2. **音量設定**：☐ ★ 三段「輕／中／大」　☐ 0–100 滑桿　☐ 不要，維持只有開關
3. **別人出牌比自己出牌輕**（−12 對 −8 dB）：☐ ★ 要　☐ 一樣大（BBO 是一樣的）
4. **一墩收走要不要有聲音**（#4）：☐ ★ 要，很輕　☐ 不要（BBO 沒有）。要的話，**我方贏墩和對方贏墩要不要不同聲音**：☐ ★ 不要（贏輸看畫面）　☐ 要
5. **叫品聲**（#7）：☐ 預設開　☐ ★ 預設關，設定裡可以開　☐ 不做
6. **合約結果**（#9）：☐ ★ 做成、倒約兩種中性的聲音（不分我方對方）　☐ 只有一種「這副結束」的聲音　☐ 不要聲音
7. **觀看別人的牌局**：☐ ★ 只有發牌、出牌、收墩，可以關　☐ 完全不出聲
8. **隊制賽另一室的比分更新**（#16）：☐ ★ 只有觀看者聽得到　☐ 參賽者也聽得到（等這一墩收走才響）　☐ 不要
9. **隊制賽結束**（#17）：☐ ★ 勝負同一聲　☐ 勝負不同聲
10. **牌桌聊天**（#11）：☐ ★ 只有聊天面板收起或分頁在背景時響　☐ 每則都響　☐ 不響
11. **手機震動**：☐ ★ 加一個「震動提醒」選項，只在「呼叫」級事件震動（iPhone 不支援，只有 Android）　☐ 不做
12. **預設**：新社員第一次進來音效 ☐ ★ 開（跟現在一樣）　☐ 關

決定之後的實作會是一個 PR：`lib/sound.ts` 加上新的聲音與節流、`PreferencesContext` 加音量與分類開關、六種語言的設定文字、`DESIGN.md` §4「音效」改寫成定案的內容，並刪掉本提案或改成「已確認」。
