## 背景

M0 的機器人打牌是規則式的（`shared/robot/play.ts`，`ROBOT.md` §3）：坐莊清王、兌現、朝大牌打；首攻照慣例；防守照社團的信號（態度反、張數正、Smith Echo、奇正偶轉、全轉換）。攤牌時用自寫的雙明手 alpha-beta（`dd.ts`，3 萬局面上限）判斷。它只用合法看得到的牌，但不猜對手的牌。

BBO 的 GIB 打牌靠「依叫牌與已出的牌抽樣 → 每副雙明手解 → 取平均」，2025 年的 GIBBO 再加上神經網路的單明手模擬（見 [`01-bbo-competitive-analysis.md`](01-bbo-competitive-analysis.md) §4）。產品需求第 1 點要「可以設定 GIB level（橋士組、公開組、大專、初學者）」，而且要比 BBO 厲害。E6 負責：

1. **打牌大腦**：DDS、單明手模擬、首攻、防守推論，並修正 GIB 的雙明手偏差。
2. **TKB 與 TKB Adv**：原本是四個等級加自訂；社長 2026-10-24 改成不分等級，只有 TKB（現在最強的規則機器人）與之後有伺服器 DDS 的 TKB Adv，差距用數字量出來。
3. **評測**：機器人對機器人的複式對抗、CI 門檻、和 BBO 的 GIB 牌局比對、和開源 Ben 對打。
4. **學習**（M3）：用牌局訓練估墩與叫牌模型。

**最大的技術限制**：Cloudflare 免費方案每次請求只有 10 ms CPU（`CLAUDE.md` 已知陷阱）。現在的規則機器人和 3 萬局面的攤牌判斷剛好塞得進去，蒙地卡羅模擬塞不進去。所以 M1 第一件事是決定機器人運算放在哪裡（AC-6.5）。

## 目標

- 機器人運算有自己的環境，牌桌不會因為機器人思考而卡住（思考上限 2 秒，逾時用規則機器人）。
- 高效 DDS：完整 DD 表 < 1 秒、單一局面 < 20 ms。
- 機器人：TKB（兩種叫牌制度），之後加 TKB Adv；不分等級。
- 評測平台與 CI 門檻：機器人相關 PR 退步就不能合併。
- M2：單明手模擬出牌、首攻模擬、防守推論、可解釋；和 BBO 的 GIB 牌局比對、對 Ben 常設對抗。
- M3：估墩與叫牌模型，通過評測門檻才上線。

## 非目標

- 叫牌規則與制度：歸 E5。
- 在瀏覽器跑機器人：機器人要看的牌只在伺服器，不送到瀏覽器（`CLAUDE.md` 硬性規則 2）。

## 需求

### TKB 與 TKB Adv（社長 2026-10-24 決定：不分等級）

原本的需求是四個等級加自訂（初學者、大專、公開組、橋士組，產品需求第 1 點的「GIB level」）。B5、B6 做了等級模型、等級 v1、選等級與刻意失誤（`e6-t18`～`e6-t21`），社長 2026-10-24 改成：

> 不分等級。沒有 DDS 之前只訓練一個機器人——現在最強的那個——取名 **TKB**（像 BBO 的 GIB）。之後伺服器加上 DDS，再有第二個 **TKB Adv**。最多就這兩個。兩種叫牌制度都留：機器人可以打淡江制度或 2/1（GIB 相容）。

| | TKB（現在，免費方案） | TKB Adv（伺服器 DDS 之後，Phase P） |
| --- | --- | --- |
| 制度 | 淡江制度或 2/1，完整規則 | 同 TKB，加模擬輔助叫牌（M2） |
| 推論 | 四家叫牌＋已出的牌（`reading.ts`） | 同 TKB，抽樣時依信號加權 |
| 防守信號 | 打並讀 | 打並讀，依信號抽樣 |
| 出牌 | 規則 | 規則＋DDS 殘局、單明手模擬（M2） |
| 刻意失誤 | 無 | 無 |
| 思考時間 | 立即 | ≤ 2 秒（逾時用 TKB） |

- TKB 就是 B5 時的「大專」：每條規則、讀叫牌與數牌、信號都開。B8 的量測顯示初學者比較弱幾乎全是 15% 刻意失誤造成的，公開組打得跟大專一樣，所以拿掉等級不會讓最強的機器人變弱。
- 教學用的「自訂」參數不做；需要弱一點的練習對手時另開 task。

### 功能

- `RobotBrain` 介面：輸入只有合法 `View`、叫牌過程、雙方制度；輸出動作與說明（含抽樣摘要）。TKB Adv 從這裡換進來。
- 評測平台：固定牌組、兩桌換位（同一組牌兩邊各打一次）、IMP／副與 95% 信賴區間、MP 百分比。
- BBO 比對：匯入 BBO 的 LIN（例如社員和 GIB 打的牌），在每個決策點重跑我們的機器人，報告與 GIB 不同的決定與 DD 損益。

### 非功能

- 機器人只用合法看得到的牌（`CLAUDE.md` 硬性規則 6），抽樣時也不讀 `state.hands`。
- 機器人是確定性的：同樣的牌、同樣的動作序列 → 同樣的決定（挑戰的公平性依賴這一點，E7 AC-7.3）。TKB 沒有亂數；TKB Adv 抽樣用的亂數以「牌局（挑戰是挑戰 id＋第幾副）＋動作序號」為種子。
- 機器人思考不阻塞 Durable Object：非同步呼叫，逾時用規則機器人。

## 設計方向

```
ClubService ──RobotBrain 介面──► 規則機器人（shared/robot，同步，免費方案內）
                              └─► 機器人運算環境（M1 決定：付費 Worker／Container／外部主機）
                                    ├─ DDS（Bo Haglund DDS，Apache-2.0，原生或 WASM）
                                    ├─ 抽樣器（E5 的推論約束＋已出的牌＋信號權重）
                                    └─ 模型（M3，ONNX）
eval/                      評測指令列：固定牌組、對抗、報告；CI 跑 200 副快速版
```

- 規則機器人永遠是後備：機器人運算環境逾時或掛掉時，牌桌照樣能打。
- 雙明手偏差的修正：防守時，對「莊家看不到的牌」不讓抽樣中的莊家「猜對」，改以莊家的單明手視角評估他的選擇；做莊時把「飛牌成功後的機率更新」「受限選擇」納入抽樣權重。

## 風險與對策

- **運算成本**：模擬只在 TKB Adv 啟用；DDS 結果快取（同一局面不重算）；`e6-t09` 的決策要附每月成本估算。
- **模擬讓牌桌變慢**：思考上限 2 秒，逾時用規則機器人；機器人出牌本來就有 1.4 秒節奏，思考可以和動畫重疊。
- **TKB Adv 的差距量不出來**：先確認評測平台的雜訊（同一機器人自己對打應該約 0 IMP），再量 TKB Adv 對 TKB。
- **「比 GIB 強」難以宣稱**：只用可重現的評測數字說話（對 Ben、對 BBO 牌局比對），不做行銷式宣稱。
